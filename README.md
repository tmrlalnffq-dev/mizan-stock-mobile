# ميزان المخزون — Mizan Stock Mobile

تطبيق Android/iOS لإدارة المنتجات والمبيعات والمخزون والمصروفات وديون العملاء، بواجهة عربية RTL وقاعدة بيانات SQLite محلية.

## الحالة الحالية

هذه **نسخة أولية قابلة للتطوير والاختبار** وليست منتجًا محاسبيًا معتمدًا. قاعدة البيانات تبدأ فارغة ولا تُدرج بيانات تجريبية تلقائيًا. تتضمن البنية:
- تسجيل المنتجات والباركود وأسعار الشراء والبيع والكمية.
- تسجيل عملية بيع وتحديث المخزون داخل معاملة قاعدة بيانات.
- مفتاح منع تكرار (idempotency key) لكل عملية بيع.
- تسجيل المصروفات.
- سجل ديون العملاء والمدفوعات.
- تنبيه انخفاض المخزون.
- ملخص مبيعات يومي/شهري.
- تصدير نسخة احتياطية JSON واستعادتها بعد التحقق من البنية.

## المتطلبات

- Node.js LTS حديث.
- npm.
- تطبيق Expo Go على الهاتف للتجربة السريعة، أو Android Studio لبناء نسخة Android مستقلة.

## التشغيل

```bash
npm install
npx expo start
```

امسح QR من تطبيق Expo Go. على Android Emulator اضغط `a` من الطرفية. قد تتطلب بعض الميزات (خصوصًا الاستيراد/التصدير والكاميرا) جهازًا حقيقيًا وصلاحيات مناسبة.

## اختبار الأنواع

```bash
npm run typecheck
```

## هيكل المشروع

- `app/`: الشاشات والتنقل.
- `src/db/`: مخطط SQLite وعمليات قاعدة البيانات.
- `src/lib/`: التنسيق والتحقق والنسخ الاحتياطي.
- `src/components/`: مكونات الواجهة.

## قواعد مهمة

- الأسعار تُخزن كأعداد صحيحة بالهللات لتجنب أخطاء الكسور العشرية.
- كل بيع يتحقق من الكمية ويخصم المخزون داخل معاملة واحدة.
- `idempotency_key` فريد لمنع إعادة خصم المخزون عند إعادة إرسال نفس عملية البيع.
- هذه النسخة لا تحتوي على تسجيل دخول أو مزامنة سحابية؛ بيانات SQLite موجودة على الجهاز. احمِ الجهاز واحتفظ بنسخة احتياطية في مكان آمن.
- استعادة النسخة الاحتياطية تستبدل بيانات قاعدة التطبيق الحالية؛ لا تستعد نسخة إلا بعد حفظ نسخة حالية.

## الفوترة الإلكترونية السعودية

هذا المشروع **ليس متوافقًا أو معتمدًا تلقائيًا** مع متطلبات ZATCA. لا يُصدر فاتورة ضريبية إلكترونية متوافقة، ولا ينفذ تكامل Fatoora أو متطلبات المرحلة الثانية (الربط والتكامل). قبل استخدامه لإصدار فواتير نظامية، يجب مراجعة متطلبات هيئة الزكاة والضريبة والجمارك حسب نوع المنشأة، وتنفيذ متطلبات الفاتورة والـ XML/UBL والتوقيع/الختم والتسلسل والتكامل والاختبارات المطلوبة، ثم التحقق من الحالة النظامية لدى الهيئة أو مستشار مختص. لا تسوّق التطبيق باعتباره معتمدًا.

## قبل الإنتاج

1. تنفيذ اختبارات آلية فعلية على قاعدة البيانات ومعاملات البيع والاستعادة.
2. مراجعة معالجة الضرائب والمرتجعات والإلغاء والوحدات والعملات.
3. تشفير النسخ الاحتياطية الحساسة، وإضافة مصادقة وقفل للتطبيق إن لزم.
4. تنفيذ تصدير تقارير PDF/CSV ومراجعة التقريب المالي.
5. إجراء اختبارات على أجهزة Android فعلية، وفحص أمان واعتمادية.
6. تثبيت إصدارات الحزم عبر `package-lock.json` بعد `npm install`.
